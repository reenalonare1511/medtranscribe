01

Executive Summary

MedTranscribe is a locally-hosted web application that enables licensed physicians to record, transcribe, and document patient consultations without transmitting audio to external servers. The application uses Gemini AI for transcription and SOAP note generation, with a PII scrubbing layer applied before any data leaves the device.

DimensionDetail
Product TypeLocal-first web app (FastAPI + HTML/JS)
Primary UserGeneral practitioners, outpatient clinics in India
Core ValueAutomated SOAP documentation with zero audio cloud exposure
AI StackGemini 1.5 Flash (transcription) + Gemini 2.5 Flash (SOAP generation)
StorageBrowser localStorage only — no backend database
DeploymentSingle-machine; doctor runs on own Windows/Mac device
Current StageV1 — working prototype, desktop only
V2 TargetMobile PWA, patient ID registry, EMR export

Why Now

  • India has 1.3M+ registered allopathic doctors with minimal structured documentation tooling
  • Average consultation is 2–5 minutes; manual note-taking reduces clinical attention
  • Existing cloud transcription tools (Nuance, Suki) are priced for US hospital systems
  • DPDP Act 2023 creates liability for patient data sent to foreign servers
  • No India-first, privacy-first, Hinglish-capable transcription tool exists at this price point
V1 Scope Boundary

Single-session transcription → SOAP note → PDF export. Patient identity managed by doctor. No cloud audio. No registration required. Estimated cost per session: <₹0.50 at current Gemini pricing.

User Stories

Recording & Transcription

US-01 · Recording
"As Dr. Anand, I want to start recording a consultation with one tap so I can focus entirely on the patient."
Acceptance Criteria: Single mic button tap starts recording. Timer starts immediately. Microphone permission requested only once.
US-02 · Pause & Resume
"As Dr. Anand, I want to pause the recording when a nurse interrupts so unrelated conversation is not captured."
Acceptance Criteria: Pause button available during recording. Timer pauses. Audio captured only during active recording state.
US-03 · Hinglish Transcription
"As Dr. Anand, I want my Hinglish consultation transcribed accurately so I do not have to correct every line."
Acceptance Criteria: Hindi words preserved in Roman script (e.g. 'bukhar' not 'fever'). Medical terms remain in English. WER <20% on Hinglish test set.
US-04 · Transcript Review
"As Dr. Priya, I want to edit the transcript before generating the SOAP note so I can correct errors before they propagate into the clinical record."
Acceptance Criteria: Transcript in editable textarea. Word count shown. SOAP generation uses the edited version.

SOAP Note Generation

US-05 · SOAP Generation
"As Dr. Priya, I want a structured SOAP note so I can copy it into the hospital HIS without reformatting."
Acceptance Criteria: All 5 sections present (CC, S, O, A, P). Hindi translated to English. Generated within 20 seconds.
US-06 · Patient Context on Note
"As Dr. Anand, I want the patient name and session timestamp on the SOAP note so I know which patient it belongs to."
Acceptance Criteria: Optional patient name input. Name and auto-generated date/time appear on note header.
US-07 · Copy to EMR
"As Dr. Priya, I want to copy the SOAP note to clipboard so I can paste it into the hospital EMR."
Acceptance Criteria: Copy button copies plain text. Button shows 'Copied!' for 1.8 seconds. No markdown in copied text.
US-08 · Print / PDF Export
"As Dr. Anand, I want to print or save the SOAP note as a PDF to attach to the patient's paper file."
Acceptance Criteria: Print button triggers browser print dialog. Print CSS hides all UI chrome. PDF save works via 'Save as PDF'.

Privacy & History

US-09 · PII Protection
"As Dr. Anand, I want patient identifiers automatically removed from the transcript before it is sent to AI."
Acceptance Criteria: 8 PII patterns scrubbed before API call. Tokens: [PHONE], [ID], [EMAIL], [NAME], [DATE], [ADDRESS]. Coverage >95%.
US-10 · Session History
"As Dr. Anand, I want to access previous session notes so I can review what I documented for a returning patient."
Acceptance Criteria: History drawer shows date, time, and CC summary. Click to reload full note. Max 100 notes. Individual delete and clear-all supported.
US-11 · Error Recovery
"As Dr. Anand, I want a clear error message when something goes wrong so I know what to do next."
Acceptance Criteria: Error banner for: mic denied, API failure, empty transcript, quota exceeded. Each includes human-readable message and suggested action.

Product Workflow

Full session lifecycle from doctor action to note export. All audio processing occurs on-device. Only the PII-scrubbed transcript reaches the Gemini API.

Doctor
Opens MedTranscribe on localhost:8000 — enters patient name (optional)
Record
Taps microphone button — MediaRecorder captures audio as WebM/Opus — timer counts up — pause/resume available
Stop
Taps Stop Recording — audio blob assembled from chunks — sent to /transcribe endpoint
Gemini AI
Audio written to OS temp file → uploaded to Gemini 1.5 Flash File API → transcript returned → temp file deleted
PII Scrub
8 regex patterns strip phone numbers, Aadhaar, PAN, emails, names, dates, addresses → clean transcript only
Review
Doctor reviews transcript in editable textarea — corrects errors before SOAP generation
Gemini AI
Clean transcript sent to Gemini 2.5 Flash → structured SOAP note generated → Hindi translated to English
Review
Doctor reviews SOAP note — patient name and timestamp displayed — note auto-saved to localStorage
Export
Copy to clipboard for EMR paste — or Print / Save as PDF for paper records
Privacy Guarantee

Audio bytes are written to OS temp directory only and deleted immediately after Gemini upload completes. The transcript string is explicitly deleted from server memory after SOAP generation. No audio or transcript is ever logged, stored, or persisted server-side.

Technical Architecture

Frontend

  • Single-file HTML/CSS/JS — no framework, no build step, no CDN dependencies
  • MediaRecorder API for audio capture (WebM/Opus primary, MP4 fallback for Safari)
  • Fetch API for /transcribe and /generate-note endpoints
  • localStorage for note persistence (max 100 notes, 4MB soft cap with warning)
  • 7 UI states managed via CSS class toggling on screen divs

Backend

  • FastAPI (Python) running on localhost:8000 via Uvicorn ASGI server
  • CORS restricted to localhost:8000 and 127.0.0.1:8000 — no wildcard
  • Lifespan context manager for model initialisation on startup
  • 4 endpoints: GET /, GET /health, POST /transcribe, POST /generate-note

AI Models

  • Gemini 1.5 Flash — audio transcription via File API upload with audio/webm MIME type
  • Gemini 2.5 Flash — SOAP note generation via text completion with clinical system prompt
  • Both via google-generativeai SDK with REST transport (truststore for Windows SSL)

DPDP Act 2023 Alignment

Under India's Digital Personal Data Protection Act 2023, patient health data is classified as sensitive personal data. MedTranscribe's local-first architecture ensures identifiable audio is never transmitted, significantly reducing data principal risk compared to cloud transcription alternatives.

Future Roadmap

Phase 1 — V1 (Current · April 2026)

Desktop-only · Single-doctor · Local deployment
  • Audio recording with pause/resume via MediaRecorder API
  • Gemini AI transcription — Hinglish-capable via Gemini 1.5 Flash
  • PII scrubbing with 8-pattern regex before any API call
  • SOAP note generation via Gemini 2.5 Flash
  • Patient name + auto-generated timestamp on notes
  • Session history in localStorage — max 100 notes
  • Print / Save as PDF and Copy to clipboard export
  • Comprehensive error handling for all known failure modes

Phase 2 — V2 (Sep 2026)

Mobile-first · Multi-session · Patient registry

  • Patient ID registry with persistent records across visits
  • Language selector — Hinglish / English / Hindi before recording
  • Audio waveform visualiser during recording
  • Doctor profile settings — name, clinic, specialisation pre-filled in notes

  • Improved PII scrubbing with NER model augmentation
  • HTTPS via local certificate; Content Security Policy headers

Clinic-ready · Multi-user · EMR-integrated

  • Hosted cloud option for clinics without IT capability
  • Audit log for DPDP Act 2023 compliance
  • Specialty-specific SOAP templates — cardiology, OB-GYN, paediatrics
